# Prompts 14-16 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver verified Stripe ingestion, explicit idempotent Stripe-to-license policy, and the final roadmap acceptance/documentation convergence.

**Architecture:** Persist only verified Stripe events in a protected durable inbox, claim them with PostgreSQL leases, normalize provider state behind an injectable adapter, and apply billing policy transactionally through existing license/audit/email services. Keep all provider IDs in dedicated mapping tables and all licensing authority in internal models.

**Tech Stack:** .NET 10, ASP.NET Core Minimal APIs/Blazor/OpenAPI, EF Core 10, Npgsql/PostgreSQL 18, Stripe.net 52.2.0, xUnit, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-08-14-prompts-14-16-design.md`

## Global Constraints

- Branch from `dev`; preserve unrelated changes and commit after every roadmap stage.
- Use Stripe API version `2026-07-29.dahlia` and Stripe.net 52.2.0.
- Verify untouched webhook bytes before parsing or persistence.
- Stripe is an adapter; signed license metadata contains no provider IDs, objects, payment data, or secrets.
- Automated tests use official signature fixtures plus fake provider/email adapters and make no live Stripe calls.
- Default grace is 7 days; refund/dispute default to review and suspend only by explicit configuration.
- Cookie billing mutations require antiforgery; scoped bearer mutations do not.
- Keep forward migrations unless exact resource inspection establishes a safe reason to re-baseline.
