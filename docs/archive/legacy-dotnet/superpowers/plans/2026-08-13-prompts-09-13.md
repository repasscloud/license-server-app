# Prompts 09-13 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver secure operator administration, scoped bearer credentials, the complete administration API, durable MailerSend-backed email, and restricted passwordless customer access.

**Architecture:** Extend the existing .NET 10 monolith with focused scoped services and PostgreSQL entities. Keep UI and API behavior on shared domain services, reuse permission policies for cookie and bearer principals, isolate customer authentication in a separate cookie, and persist secrets only as versioned HMACs or Data Protection ciphertext.

**Tech Stack:** .NET 10, ASP.NET Core Identity/Minimal APIs/Blazor/OpenAPI, EF Core 10, Npgsql/PostgreSQL 18, xUnit, MailerSend HTTP API.

**Spec:** `docs/superpowers/specs/2026-08-13-prompts-09-13-design.md`

## Global Constraints

- Branch from `dev`; preserve unrelated changes and commit after every roadmap stage.
- Administrators never choose another human user's reusable password.
- Plaintext invitation, reset, API-key, activation-code, and customer-challenge secrets are one-time responses and never enter logs or audit.
- Cookie mutations require antiforgery; explicit bearer mutations do not.
- UI and API call the same domain services and permission policies.
- All new persistent state is introduced by forward EF Core migrations.
- Production email configuration and peppers come only from secret configuration.
